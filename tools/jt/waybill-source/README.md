# بوليصة شحن عتبة × J&T Egypt — نموذج للاعتماد (100 × 150 مم)

نموذج تجريبي لبوليصة شحن مطبوعة من طرف `SAHL` على بوليصة `J&T`، بمقاس `100 × 150 mm` للطباعة الحرارية بالأبيض والأسود.
**هذا نموذج للمراجعة فقط — غير معتمد من J&T لحد ما يردوا.**

## محتويات الحزمة

| الملف | الوظيفة |
|---|---|
| `waybill-template.html` | الـ `template` الأساسي (HTML + CSS بوحدات mm) — ده الملف اللي بتعدّل فيه التصميم |
| `build_waybill.py` | `Build script`: بياخد `JSON` ويطلّع `PDF` + `HTML` جاهز + `PNG` للمعاينة + تقرير `QA` |
| `data.sample.json` | بيانات النموذج التجريبي (3 منتجات) |
| `data.long-order.json` | بيانات طلب طويل (11 منتج + ملاحظة) لتوضيح التصغير التدريجي |
| `data.huge-order.json` | بيانات طلب ضخم (24 منتج + ملاحظة) لتوضيح أقصى حالة على صفحة واحدة |
| `annotate_preview.py` | بيرسم مربعات القياس (الباركود وكود الفرز) على صورة المعاينة لمراجعة الـ IT |
| `assets/` | لوجو عتبة بالأسود (`3ataba-logo-wordmark-black.png` المستخدم في الهيدر، و`3ataba-logo-full-black.png` بالشعار «أرخص سعر في مصر») |
| `fonts/` | `Cairo` (عربي + لاتيني، أوزان 400/700/800) و `Liberation Sans` (بديل `Arial` بنفس المقاسات) — بيتضمّنوا داخل الـ PDF |
| `out/` | آخر ملفات تم تصديرها |

## إعادة البناء

المتطلبات: `python3` مع `jinja2` و `python-barcode` و `playwright` (مع `chromium`) و `pymupdf`، بالإضافة إلى `poppler-utils` (`pdftoppm` / `pdfinfo` / `pdffonts`).

```bash
pip install jinja2 python-barcode playwright pymupdf && playwright install chromium
python3 build_waybill.py data.sample.json --out out --name 3ataba-JT-waybill-sample --png
python3 build_waybill.py data.long-order.json --out out --name long-order-demo --png
python3 build_waybill.py data.huge-order.json --out out --name huge-order-demo --png
```

خيارات مفيدة:

- `--barcode-module 0.5` لو J&T فضّلوا `module width` ثابت مضاعف لنقطة الطابعة (4 نقاط على 203 dpi → العرض يبقى 72.5 مم بدل 70).
- `--link-fonts` لو عايز الـ HTML الناتج يشاور على مجلد `fonts/` بدل تضمينهم `base64`.
- `--logo assets/3ataba-logo-full-black.png` لو عايز النسخة الكاملة من اللوجو بالشعار (الافتراضي الـ wordmark بس لأن الشعار بيبقى صغير جدًا على الطباعة الحرارية).
- `--vbarcode-length 60 --vbarcode-bar 9` لتغيير طول/ارتفاع الباركود الرأسي (لازم العمود يفضل أطول من الباركود بـ 8 مم على الأقل عشان الـ `quiet zones`).

الـ HTML اللي بيطلع في `out/` ملف واحد مستقل (الخطوط مضمّنة): تقدر تفتحه في المتصفح، تعدّل النص، وتطبع بـ `Actual size / 100%` على ورق `100 × 150`.

## نهج الملاحظات (Remark)

زي ما بيحصل في J&T: مفيش خانة للمنتجات، فالمنتجات بتتكتب في الـ `remark`. الـ `template` بياخد نفس النص اللي `SAHL` هيبعته في خانة `remark` للـ `API` بتاع J&T وبيطبعه كما هو، سطر سطر، بخط كبير — من غير أي تنسيق إضافي ومن غير ما يقص أو يختصر أي حاجة. تحت القسم فيه سطر ثابت «يسمح بالمعاينة أمام المندوب» (تقدر تغيّره أو تشيله بالحقل `remark_footer` في الـ `JSON`).

## الطلبات الطويلة — صفحة واحدة دايمًا

البوليصة بتتلزق على الطرد، فمفيش صفحة تانية نهائيًا. الـ `build script` بيقيس المساحة الفعلية في `Chromium` وبينزل سلّم التصغير خطوة خطوة لحد ما النص كله يدخل:

1. **وضع القائمة** (كل منتج في سطر): الخط بيبدأ 13 pt وينزل نص نقطة نص نقطة لحد 9 pt — ده بيغطي لحد حوالي 11–12 سطر مع عنوان قصير.
2. **وضع الفقرة (`flow`)**: لو لسه مش داخل، السطور بتتكتب ورا بعض في فقرة واحدة مفصولة بنقطة «•»، والخط بيبدأ 10 pt وينزل لحد 6.5 pt — ده بيغطي حوالي 25 سطر.
3. لو حتى 6.5 pt مش كفاية (نادر جدًا — أكتر من ~25 سطر)، الـ script بيطبع تحذير `WARNING` في الـ `terminal` وآخر السطور بتتقص؛ الحل وقتها إن `SAHL` يختصر نص الـ `remark` للأوردر ده.

أمثلة جاهزة: `out/3ataba-JT-waybill-long-order-demo.pdf` (12 سطر → 9 pt فقرة) و`out/3ataba-JT-waybill-huge-order-demo.pdf` (25 سطر → 6.5 pt فقرة).

## شكل الـ JSON

```json
{
  "sample": true,
  "waybill_no": "UEG088902573105",
  "service_type": "Standard",
  "sorting_code": "20 C01-03",
  "cod_amount": 450, "weight_kg": 1,
  "recipient": { "name": "...", "phone": "01000000000", "phone_alt": "01100000000",
                 "governorate": "القاهرة", "city": "مدينة نصر", "address": "..." },
  "sender": { "name": "عتبة", "brand_en": "3ataba.com", "phone": "...", "address": "..." },
  "remark": "عدد 2 تيشيرت أسود مقاس L\nبنطلون بيج مقاس 32\nتيشيرت أبيض مقاس M",
  "remark_footer": "يسمح بالمعاينة أمام المندوب",
  "jt_hotline": "15865",
  "printed_at": "2026-09-17 14:10"
}
```

`remark` هو نفس النص اللي بيتبعت لـ J&T (الأسطر مفصولة بـ `\n`) وبيتطبع زي ما هو. لو بعت `items` (قائمة منتجات منظّمة) بدل `remark`، الـ script بيركّب منها النص بالصيغة `عدد N name color مقاس size`.

`sample: true` بيطبع تنويه «نموذج تجريبي — غير صالح للشحن». في الإنتاج خلّيها `false` (وممكن تحط نص بديل في `footer_note`).

## نقاط لازم تتأكد من J&T قبل الربط

1. **نوع ترميز الباركود**: النموذج بيستخدم `Code 128` (auto subset) — الشائع في بوالص J&T، لكن الدعم لم يؤكده.
2. **عرض الـ module**: 70 مم ÷ 145 module = 0.483 مم (≈ 3.9 نقطة على 203 dpi). الباركود اتفك بنجاح في محاكاة 203 dpi بدون anti-aliasing، لكن لو طابعاتهم عايزة module مضاعف صحيح للنقطة استخدم `--barcode-module 0.5`.
3. **اللوجو الرسمي**: `J&T EXPRESS` مكتوب كنص مؤقت — محتاجين ملف اللوجو منهم وموافقتهم على مكانه (أعلى يسار زي نموذجهم).
4. **مصدر الكود الثلاثي**: `20 C01-03` مثال شكلي؛ في الإنتاج لازم يجي من رد الـ `API` بتاعهم لكل بوليصة.
5. **خط رقم البوليصة وكود الفرز**: `Liberation Sans Bold` (مقاسات `Arial Bold` نفسها) — كود الفرز 20 pt عرضه 33.6 مم داخل الـ 35 مم.
6. **رقم خدمة العملاء في الـ Footer**: مكتوب `15865` زي ما قريته من صورة نموذجهم — لازم يتأكد منهم (الحقل `jt_hotline` في الـ `JSON`).
8. **الباركود الرأسي**: نفس رقم البوليصة بـ `Code 128`، طول 54 مم و`module` 0.372 مم (≈ 3 نقاط على 203 dpi) — اتفك بنجاح في محاكاة 152/203/300 dpi، لكن يفضّل يعملوا `test scan` عليه على طابعاتهم.
7. **الحد الأقصى لطول خانة `remark`** في الـ `API` بتاعهم — عشان `SAHL` يقص النص اللي بيتبعت ليهم لو أطول من المسموح (البوليصة عندنا بتطبع النص كامل مهما كان طوله).
